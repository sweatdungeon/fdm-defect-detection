## B. Errors, limitations and unhelpful output

Every error below was made or missed by the AI and caught before results were
reported. None changed a reported result after it was published.

| # | Error | How it was caught | Fix |
|---|---|---|---|
| 1 | `extract_subset.py` (present before the session) matched images only under an `images/` folder; the Kaggle `images.zip` stores them at the top level, so it would have extracted 0 images | Claude Code listed the zip's contents before running the script | match with or without the prefix |
| 2 | `split_by_print` used Python `round()`, which rounds halves to even (`round(4.5) == 4`), giving unintended split sizes | failing test `test_split_no_training_prints_left` | round halves up explicitly |
| 3 | A random-forest reproducibility test required exactly equal probabilities; it failed by 2e-16 because parallel trees are summed in thread order | failing test | compare with 1e-12 relative tolerance (the trees are identical) |
| 4 | A leave-one-group-out test fixture gave two "printers" only one class (recall undefined) | failing test | test data fixed; the code was correct |
| 5 | The first full pipeline run crashed (pandas 3 strings saved as an object array that NumPy will not load without pickle), and **the crash was hidden** because the shell pipe reported `grep`'s exit code 0 | Claude Code read the log instead of trusting the exit code | dtype fixed; reran with `pipefail` |
| 6 | pdoc wrote the absolute local path (including the Windows user folder) into the HTML docs | scan of generated files before committing | `scripts/build_docs.py` strips the machine-specific prefix |
| 7 | Two reStructuredText tables in docstrings rendered as raw text in pdoc | inspection of rendered pages | converted to Markdown tables |
| 8 | A README draft stated the results came from an "Intel CPU", which was never checked | self-review before committing | changed to "Windows laptop CPU" |
| 9 | References were first written from the AI's memory and not checked against the sources | flagged by Claude Code as unverified | replaced with my verified list |
| 10 | Figure layout problems (label collisions, a large gap between panels) | rendering and inspecting every figure | layout fixed |
| 11 | The report script first used `DataFrame.to_markdown`, which needs an uninstalled package | self-review before running | wrote the table directly |

**Limitations of the AI's work that remain:**
- The colour palette for the figures could not be checked with its validator
  script (Node.js not installed); Claude Code relied on the palette's
  documented test results instead.
- The dataset licence could not be read by the AI (the Kaggle page requires
  sign-in); the licence section in `data/README.md` records my reading.
- Claude Code ran leave-one-printer-out only for the baselines, as specified.
  Whether the CNN generalises to an unseen printer is untested.

### 2026-10-24: Repository and data setup

**Task.** Ignore the raw data in git, set up a Python virtual environment, extract
the image subset from the Kaggle zip, and commit.

**What the AI did**
- Added `data/raw/` and `*.zip` to `.gitignore` so images and archives are never
  committed.
- Created a `.venv` virtual environment (Python 3.12.15 via `uv`, since Python
  was not installed system-wide) and installed pandas 3.1.0.
- Identified `Downloads/images.zip` (12.2 GB) as the Kaggle image archive by
  checking its entry count: 106,339 = 81,060 train + 25,279 test images.
- Found and fixed a bug in `scripts/extract_subset.py` (error B1): it only
  matched images stored under an `images/` folder inside the zip, but
  `images.zip` stores them at the top level, so it would have extracted 0
  images. The fix strips an `images/` prefix only if one is present.
- Ran the script to extract the 6,227 subset images into `data/raw/images/`.
- Set up git identity (my name and student email) on my instruction.

**How it was checked**
- Script output reported all 6,227 of 6,227 subset images found;
  `find data/raw -name '*.jpg' | wc -l` gave 6227.
- `git check-ignore -v data/raw/images/022` confirmed the `data/raw/` rule
  applies, and `git ls-files data/raw` listed no tracked files.

### 2026-10-25: Package structure, data module, synthetic data and tests

**Task.** Set up the package (pyproject.toml, src layout, requirements.txt,
tests) and write the data module: load and validate the subset CSV and images,
and split by print with stratification by label. Add a synthetic data
generator and tests.

**What the AI did**
- `pyproject.toml` (setuptools, src layout, package `fdm_defect`), pinned
  `requirements.txt`, README setup/usage sections.
- `src/fdm_defect/config.py`: default paths, image size (128) and seed (42).
- `src/fdm_defect/data.py`: `load_metadata` / `validate_metadata` (required
  columns, empty tables, nulls, integer dtypes, 0/1 labels, `img_path` format
  and agreement with the id columns, duplicates, prints with mixed labels or
  printers, missing files); `load_image` / `load_images`; `split_by_print`
  and `check_no_print_leakage`.
- `src/fdm_defect/synthetic.py`: bead-stripe image generator and a writer that
  produces a dataset in the real folder/CSV layout.
- 59 tests, including one on the real subset.

**How it was checked.** 59 tests passed; a noise-free 8-bead synthetic image
has its FFT peak at index 8; all 6,227 real images load and the 52 prints split
36/8/8 with no overlap and both classes in every split.

**AI errors found.** B2 (`round()` half to even in the split).

### 2026-10-25: Hand-crafted features and baseline classifiers

**Task.** Write the NumPy feature module and the logistic regression / random
forest baseline from `CLAUDE.md`, with known-answer tests.

**What the AI did**
- `src/fdm_defect/features.py`: 43 features (16-bin grey histogram, RGB
  mean/std, 5 Sobel statistics, 10-bin uniform LBP, 4 GLCM statistics, 2 FFT
  periodicity features), NumPy only, with input validation.
- `src/fdm_defect/baseline.py`: standardised logistic regression and a random
  forest (300 trees, `min_samples_leaf=5`), both `class_weight="balanced"`.
- `scripts/run_baseline.py`; 54 new tests; scikit-learn 1.9.1 added.

**Design choices made by the AI** (see C.2): Sobel uses a "valid" convolution
(borders dropped); LBP uses the square 3×3 ring rather than interpolated
circle points; GLCM energy follows the scikit-image convention (square root of
the angular second moment); correlation is defined as 1 for a constant image.

**How it was checked.** Known-answer tests (Sobel ramp, cosine FFT,
checkerboard GLCM, hand-worked LBP patterns, step-edge density 2/6,
histogram endpoints); 113 tests passed. First real-data run on validation:
logistic regression ROC-AUC 0.715, random forest 0.798.

**AI errors found.** B3 (exact-equality reproducibility test).

### 2026-10-25: Pretrained CNN training module

**Task.** Write the MobileNetV3-Small training module from `CLAUDE.md`, with tests.

**What the AI did**
- `src/fdm_defect/cnn.py`: `build_model` (MobileNetV3-Small or ResNet-18,
  ImageNet weights, 1-logit head, frozen backbone by default);
  `set_train_mode` (frozen BatchNorm kept in eval mode); `FrameDataset`
  (uint8 cache, ImageNet normalisation, augmentation); `train_model`
  (`BCEWithLogitsLoss` with `pos_weight`, AdamW, early stopping restoring the
  best weights); `predict_proba`.
- `scripts/train_cnn.py`; torch 2.14.1 / torchvision 0.29.1; saved weights
  git-ignored; 33 tests.
- Checked in torchvision 0.29.1 that MobileNetV3-Small's 34 BatchNorm layers
  use momentum 0.01, as `CLAUDE.md` states.

**How it was checked.** Frozen BatchNorm statistics unchanged after a
training-mode pass; one epoch changes the head but not the backbone; early
stopping with lr = 0; best-weight restoration; bit-identical weights for equal
seeds; the pretrained head learns the synthetic task (≥ 80%); 146 tests passed.
